정적 내보내기 환경에서는 요청 시점에 할 수 있는 일이 없다. 폰트를 어떤 형태로 내려줄지, 어떤 글자만 남길지, 어떤 태그를 문서에 심을지가 전부 빌드 시점에 결정된다.

## 문제 상황

빌드 산출물을 정적 호스팅에 올린 뒤 첫 화면에서 글자가 잠깐 다른 얼굴로 보였다가 바뀌는 현상이 관찰됐다. 원인 후보는 세 가지였다.

- 폰트 파일이 프리로드되지 않아 파싱 이후에야 요청이 시작되는 경우
- 폴백 폰트의 메트릭이 실제 폰트와 달라 치환 시점에 레이아웃이 흔들리는 경우
- 서브셋 범위에서 빠진 글자가 별도 파일로 뒤늦게 요청되는 경우

세 가지는 증상이 비슷해서 눈으로는 구분되지 않는다. 네트워크 탭에서 폰트 요청의 시작 시각과 `font-display` 값을 같이 봐야 어느 쪽인지 갈린다.

## 동작 방식 확인

빌드 산출물을 직접 열어 보면 생성된 스타일에 메트릭 보정용 폴백이 함께 선언돼 있는 것을 볼 수 있다.

```css
@font-face {
  font-family: "Geist Fallback";
  src: local("Helvetica Neue");
  ascent-override: 95.9%;
  descent-override: 24.2%;
  size-adjust: 104.1%;
}
```

### 측정 절차

1. 캐시를 비운 상태로 첫 화면을 연다
2. 폰트 요청의 시작 시각을 문서 파싱 완료 시점과 비교한다
3. 같은 절차를 느린 네트워크 조건에서 반복한다

> 측정 없이 원인을 정하면 고친 것처럼 보이는 변경이 남는다. 증상이 사라진 것과 원인이 사라진 것은 다르다.

| 항목 | 프리로드 있음 | 프리로드 없음 |
| --- | --- | --- |
| 요청 시작 | 파싱 전 | 파싱 후 |
| 레이아웃 이동 | 없음 | 있음 |

## 남는 문제

가변 폰트를 쓰면 파일 하나로 굵기 전 범위를 덮을 수 있지만 파일 크기가 커진다. 어느 쪽이 유리한지는 실제로 쓰는 굵기가 몇 개인지에 달려 있어서, 프로젝트마다 다시 재는 수밖에 없다. 관련 배경은 [MDN의 font-display 문서](https://developer.mozilla.org/docs/Web/CSS/@font-face/font-display)에 정리돼 있다.
