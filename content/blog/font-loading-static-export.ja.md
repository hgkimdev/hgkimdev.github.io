静的エクスポート環境では、リクエスト時点でできることは何もない。フォントをどんな形式で配信するか、どの文字だけ残すか、どんなタグをドキュメントに埋め込むか——すべてビルド時点で決まる。

## 問題状況

ビルド成果物を静的ホスティングに上げた後、最初の画面で文字が一瞬別の書体で表示されてから切り替わる現象が確認された。原因の候補は3つあった。

- フォントファイルがプリロードされておらず、パース後にリクエストが始まる場合
- フォールバックフォントのメトリクスが実際のフォントと異なり、置き換え時にレイアウトが揺れる場合
- サブセットの範囲から漏れた文字が別ファイルとして遅れてリクエストされる場合

この3つは症状が似ていて、目で見ただけでは区別できない。ネットワークタブでフォントリクエストの開始時刻と`font-display`の値を一緒に見て初めてどれか分かる。

## 動作の確認

ビルド成果物を直接開くと、生成されたスタイルにメトリクス補正用のフォールバックが実際のフォントと一緒に宣言されているのが分かる。

```css
@font-face {
  font-family: "Geist Fallback";
  src: local("Helvetica Neue");
  ascent-override: 95.9%;
  descent-override: 24.2%;
  size-adjust: 104.1%;
}
```

### 測定手順

1. キャッシュを空にした状態で最初の画面を開く
2. フォントリクエストの開始時刻とドキュメントのパース完了時刻を比較する
3. 同じ手順を低速なネットワーク環境で繰り返す

> 測定せずに原因を決めると、直したように見えるだけの変更が残ってしまう。症状が消えたことと原因が消えたことは違う。

| 項目 | プリロードあり | プリロードなし |
| --- | --- | --- |
| リクエスト開始 | パース前 | パース後 |
| レイアウトシフト | なし | あり |

## 残る課題

可変フォントを使えば1ファイルで太さの全範囲をカバーできるが、ファイルサイズは大きくなる。どちらが有利かは実際に使う太さの数次第なので、プロジェクトごとに測り直すしかない。関連する背景は[MDNのfont-displayドキュメント](https://developer.mozilla.org/docs/Web/CSS/@font-face/font-display)にまとまっている。
